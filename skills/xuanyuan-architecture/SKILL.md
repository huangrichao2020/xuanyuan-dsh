# 玄源 · 运行架构（载体成熟度与决策闸门）

把 agent 的运行架构拆成三层，先保住干净上下文和稳定状态，再谈能力增长。

## 三层架构

```
agent 运行架构 =
  常驻最小核心
  + 触发式模块
  + 离线演化系统
```

- **常驻最小核心** = 任务包（目标/验收/边界）+ 最小上下文 + 外部工作记忆 + 执行循环 + 终态同步。普通任务只留这些。
- **触发式模块** = 深度思考、注意力治理、人文判断、实例觉察、技能/工具/记忆/多智能体。仅在触发条件真实存在时才加载。
- **离线演化系统** = 经验沉淀、回放评估、能力成熟度评估、审计。默认在主线上下文之外运行，只把有用结论喂回下一轮。

## 运行时五规则

1. 先立常驻最小核心：目标、验收、边界、最小上下文、外部工作记忆、执行循环、终态同步。
2. 加任何层之前问抗膨胀三问：是否降低上下文获取成本？是否提升状态稳定性？是否加深对真实环境的理解？三项都不沾，就不加。
3. 触发式模块的真实触发出现时才加载，不要预加载。
4. 离线演化系统默认离线，只把结论（而非原始日志）喂回下一轮。
5. 把一次升级当真之前，先走回放/评估验证。

## 主路径例外

普通任务走最小核心；出现外部伤害、隐私、财务、不可逆、失控或生产事故风险时，进入主路径例外处理（强告警或显式确认）。

## 边界（防膨胀与防死循环）

- 注意力治理不是更多上下文倾倒，而是用最小有效上下文 + 运行时纠正来引导。
- 思考核心不是长推理文本，而是找本质、选策略、拆战术、回到可验证行动。
- 人文判断不是抒情装饰，必须回到真实行动，不把人压平成任务源。
- 实例觉察不是顶层架构模块，也不是删记忆，而是保意义、关旧行动环、防旧实例劫持当前主线。
- 能力成熟度评估不是硬停止层，而是让候选成长，再用回放/评估/反馈选可逆升级。
